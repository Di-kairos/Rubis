### Починенные баги (оба найдены владельцем на живом плеере)

1. **Play умирал после возврата устройства.** Наушники вынули → устройство
   умерло → `handleDeviceLoss()` поднимал `outputDeviceLost` и ставил паузу.
   `resume()` при поднятом флаге молча ничего не делал, а сбрасывался флаг
   только в `startCurrent()` — то есть при запуске трека с нуля. Воткнули
   наушники обратно — Play мёртв навсегда.
   Теперь Play поднимает текущий трек с секунды пропажи. Запрет SPEC §9 на
   авто-возобновление не нарушен: без нажатия ничего не происходит. Решение
   вынесено в чистый `ResumePolicy` (+3 теста).
2. **Альбом, переехавший между источниками, раздваивался.** Распознавание
   переноса работало только внутри одного источника: скан AMBIENT помечал
   треки недоступными (D-004), скан ELECTRO заводил их заново. Альбом один на
   обе стороны — в нём оказалось 46 треков вместо 23, половина серые с ⚠.
   Теперь новые файлы сверяются с недоступными треками **других** источников
   по подписи size+mtime — строка меняет хозяина, `id`/плейлисты/история целы.
   Плюс уборка в конце скана для неудачного порядка сканирования (новый
   источник обошли раньше старого) — сносит недоступного близнеца, у которого
   есть живой экземпляр. Оба порядка закрыты тестами на настоящих файлах.

### Фишки (по списку владельца, main)

- **C — отказ говорит словами** (`39d3dc5`): политика `rateFallback = .refuse`
  перестала притворяться поломкой. Свой случай `rateRefused` называет
  устройство и частоту («Refused: FiiO QX13 cannot do 192 kHz, and resampling
  is off»), все ошибки воспроизведения получили человеческий текст вместо
  `Error: deviceUnavailable`, опция названа политикой. Частоты форматируются
  через POSIX — на русской локали `formatted()` давал «44,1».
- **D — Network Ledger** (`917f004`): `NetworkLedger` в EscapementCore,
  событие = хост (без пути — в пути едет название альбома), причина, исход,
  размер. Заметки ходят через одну дверь `AlbumInfo.data(from:)`, проверки
  Sparkle снимаются через `SPUUpdaterDelegate` — иначе панель врала бы нулём.
  Settings → Network: счётчик, хосты с причинами и провалами, Clear log,
  «Nothing has left this machine.» на чистой установке. Хранилище — файл в
  Application Support: схема БД после фазы 2 не меняется без владельца.
- **F — аппаратная громкость** оказалась уже сделанной (`Player.deviceVolume`,
  SPEC §4.4): слайдер крутит ручку самого ЦАПа.

## Разобранное, но не баги

- `Error: deviceUnavailable` при живом плеере — `preferredDeviceUID` был прибит
  к FiiO QX13, а тот не подключён. Поведение верное (0.3.4: не убегать на
  колонки самому), плохой была формулировка — вылечено пунктом C.
- Sparkle показывал «up to date» сразу после публикации 0.8.7 — CDN
  `raw.githubusercontent.com` отдаёт фид с `max-age=300`. Через пять минут
  обновление пришло.
- Keychain-диалог при входе в настройки: записи `claude-api-key`/`deepseek-api-key`
  созданы старыми подписями (ad-hoc, `Rubis Dev`, `Rubis Dev 2`), их ACL не
  знает нынешнюю Developer ID. Лечение — удалить обе записи и ввести ключ
  заново; команды отданы владельцу (`security` целиком режется классификатором).
