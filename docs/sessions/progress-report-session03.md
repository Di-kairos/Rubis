# Progress Report — Session 03 (2026-08-07, MacBook Pro M5 Max)

## Что сделано

**Фаза 5 закрыта полностью.** Три оставшихся чекбокса + весь acceptance.

**Список треков (`App/Scenes/TracksList.swift`, новый файл, вынесен из `ArtistsList`):**
колонки `#` · Title · Artist · Album · Duration · Format, сортировка кликом по заголовку
со стрелкой, мультивыделение ⌘/⇧-кликом от `List(selection:)`, Return играет с верхней
выделенной строки, контекстное меню работает на всё выделение (поведение Finder).
Логика сортировки вынесена в пакет — `MusicLibrary.TrackSort`, поэтому под тестами:
человеческое сравнение строк (`localizedStandardCompare`), tie-break по `id`, чтобы
равные ключи не тасовались при смене направления.

**Поиск (`SearchResults.swift` переписан):** группы Artists / Albums / Tracks (SPEC §7.2),
`↓` из поля переводит фокус в результаты, стрелки ходят сквозным индексом по всем
группам, Return играет, ⌘Return в очередь, Esc сбрасывает запрос с обеих сторон.
Артисты и альбомы ищутся префиксом по нормализованному sort-ключу («bjork» → «Björk»,
«beatles» → «The Beatles»). Предикат — сравнение диапазона, а не `LIKE`: с `ESCAPE`
SQLite отключает LIKE-оптимизацию и сканирует индекс целиком, а `%`/`_` из запроса
заодно перестают быть шаблоном.

**Клавиатура во всех разделах:** общий модификатор `keyboardNavigable` для сетки
альбомов, списка артистов и колонки плейлистов (↑↓ + Return, фокус за кликом,
scroll-to-focus, клампинг индекса при live-обновлении коллекции). Горизонтальные
стрелки не трогаем — они за перемоткой (SPEC §7.6).

**Настоящий баг ввода:** `Play/Pause`, `←` и `→` висели пунктами меню без модификаторов,
поэтому AppKit раздавал их как key equivalents до того, как их видело сфокусированное
текстовое поле — пробел в поиск было не набрать. Пункты гаснут, пока курсор в поле
(`env.isEditingText`).

**Производительность (`perf(ui)` + харнесс):** загрузка 100k с именами 1.56 с,
сортировка с индексом позиций ≤ 0.4 с (release). Обе операции лежали на MainActor —
уведены в detached-задачи, счётчик поколений отбрасывает устаревшие сортировки,
на время первой загрузки показывается состояние загрузки.

**In-process харнесс (`App/DebugHarness.swift`, только DEBUG)** — то, что я сперва
ошибочно объявил неизмеримым:
- прокрутка списка с постоянной скоростью + съём интервалов display link;
- снимок окна через `cacheDisplay` (прав Screen Recording не требует, в отличие от
  `screencapture`);
- генератор синтетической библиотеки — тест `generateLargeLibraryFixture`.

Замеры на 100k, debug-сборка: **59 fps при 2000 pt/с (0.8% опозданий), 60 fps без
опозданий на 6000 и 12000 pt/с**, дисплей 60 Гц. Память с открытым списком:
50k → 221 МБ при бюджете §12 250 МБ, 100k → 311 МБ.

**Что поймали снимки окна, чего не поймало ни одно ревью по коду:** заголовок
«DURATION» обрезался в «DURATI…» на 56 pt; название трека душилось равной третью,
пока у артиста и альбома оставался запас. Плюс собственная регрессия при починке:
фиксированная `width` съела Title целиком в узком окне — нужен `maxWidth` (кап).

## Решения в серых зонах

- **SwiftUI `List` остаётся, `NSTableView` из SPEC §7.4 не нужен** — `List` и так
  `NSTableView` под капотом, бюджет держит (цифры выше).
- `SearchHit` переиспользован как строка списка, а не заведён новый тип: та же форма
  (трек + имена), плюс он стал `Identifiable` для `List(selection:)`.
- `TrackRepository.all()` удалён вместе с последним вызовом (осиротел от правки).
- `allWithNames()` без `ORDER BY` — порядок всё равно задаёт `TrackSort` в UI.
- Бюджеты perf-теста разведены по конфигурации (`#if DEBUG`): в debug те же операции
  медленнее в 4–5 раз, иначе порог пришлось бы задрать до бессмысленного.
- Индекс `(artist_id, album_id, disc_no, track_no)` под `tracks(byArtist:)` **не добавлен** —
  это правка схемы после фазы 2, требует явного согласия владельца.

## Codex-ревью

Каждый кусок прогнан через ТриМозга → Codex. Найдено и починено до коммита 12+ дефектов,
самые серьёзные:
1. У `SearchHit` не было `public init` — Debug-сборка легла бы на `#Preview` в app-таргете
   (Release этого не ловит, превью под `#if DEBUG`).
2. Сортировка считалась в `body` — полный пересорт 100k на каждое изменение выделения.
3. Клик по заголовку во время загрузки навсегда оставлял список пустым.
4. Нет tie-breaker'а: `reversed()` тасовал равные ключи при смене направления.
5. `LIKE ... ESCAPE` отключает индексный seek в SQLite.
6. Потерянный первый `↓` из поиска, пока идёт дебаунс.
7. Двойной `select()` на клик (tap + onChange) — двойная загрузка альбомов артиста.
8. `env.renamingPlaylist` залипал `true` при уходе с раздела и глобально гасил Space.
