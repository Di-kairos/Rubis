## D-001 · 2026-08-06 · ЦАП не выбран — строим универсально

Di-kairos пока не выбрал ЦАП/интерфейс. Реализация по спеке без допущений о железе:
`Settings.dsdMode = .dopIfAvailable`, полный набор тестовых частот 44.1–192 кГц в
`audio-verify`. Конкретное железо уточняется к фазе 3 — тогда же ручные проверки DoP.

## D-002 · 2026-08-06 · Библиотека и на внутреннем SSD, и на внешнем томе

Несколько локальных источников (таблица `source` это уже допускает). Следствия:
security-scoped bookmarks обязательны для всех источников; поведение при отключении
внешнего тома (X10 Pro) — треки источника приглушаются, скан не падает, как SPEC §6.3
для оффлайн-сервера, но для локального тома.

## D-007 · 2026-08-06 · Визуальная идентичность Rubis: «Jewel Box», спокойная, без агрессивного красного

Направление Di-kairos: оригинальное приложение (не Apple Music-клон), идентичность от
имени RUBIS и рубиновой иконки, ничего агрессивного. Реализация:
- палитра теплее и глубже (bg тёмного — тёплый почти-чёрный #100D10 фона логотипа),
  выделение — золотая дымка вместо серой заливки;
- **serif-дисплей** (New York) для названий альбомов/артистов/заголовков — главный
  типографический знак отличия (заменяет прежнее «как в Apple Music» из DESIGN §3);
- новый токен `gem` (приглушённый гранат #A85868/#8A4351) — ТОЛЬКО ◆-маркер играющего
  трека, единственный «рубиновый» элемент; агрессивного красного в UI нет;
- сайдбар: активный раздел — золотая нить слева, не заливная пилюля; выбранный альбом —
  тонкое золотое кольцо вокруг обложки.
WCAG-тесты контраста прошли на новой палитре. Дальнейшие визуальные решения — через
токены DesignSystem, литералы вне пакета по-прежнему запрещены.

## D-006 · 2026-08-06 · Non-goals §1.3 частично сняты владельцем: EQ/DSP, стриминги, скробблинг → бэклог

## D-005 · 2026-08-06 · Autoupdate через Sparkle — отмена запрета SPEC §13

Di-kairos попросил автообновления (нужно раздавать сборку другу). Отменяет «никакой
автообновляемости» из SPEC §13. Реализация: Sparkle 2 (4-я зависимость сверх SPEC §3.2,

Subsonic (когда появится) + фид обновлений.

## D-004 · 2026-08-06 · Пропавший файл не удаляется из библиотеки (`track.unavailable`)

Разбор strawberry (сессия 02) показал дыру: скан удалял треки, чьих файлов нет на месте.
Отключённый внешний том (D-002) или переименованная папка выкашивали записи вместе с
плейлистами и историей (FK `ON DELETE CASCADE`). Решение по образцу их
`collectionwatcher` (song tracking + `mark_songs_unavailable`):

1. Пропавший путь сперва сопоставляется с новыми путями по `size+mtime` — перенос узнан,
   трек сохраняет `id`.
2. Остальные помечаются `unavailable = 1` (миграция `v2_track_unavailable`), в UI строка
   приглушена с иконкой и путём в тултипе (SPEC §9), в очередь не попадает.
3. Файл вернулся — пометка снимается на следующем скане.

Удаления треков в скане больше нет вообще; чистка «мёртвых» строк — отдельное осознанное
действие, когда понадобится. Сигнатура переноса — `size+mtime`, без хеша содержимого:
коллизия возможна, лечится хешем, если всплывёт.

## D-008 · 2026-08-08 · Аннотации альбомов: Wikipedia → Claude API, opt-in

Запрос владельца: краткая информация об альбоме на его экране. Ревизия правила
«исходящие соединения — только включённые владельцем»: добавлены два источника,
оба за явным opt-in (Settings → General → Album notes, по умолчанию выключено).

1. **Wikipedia REST** (без ключа): search/title → page/summary, берём extract
   страницы type=standard длиной ≥ 150 символов.
2. **Claude API** (fallback, `claude-opus-5`): 2–3 абзаца liner notes; ключ
   владельца хранится в Keychain (`KeychainStore`), не в UserDefaults и не в git.

Результат кешируется навсегда в `Application Support/Escapement/album-info/`
(файл на альбом) — сеть трогается один раз. Источник честно подписан в UI
(«From Wikipedia» / «Notes by Claude»). Язык аннотаций — английский, как весь UI
(ASSUMPTION; меняется одной строкой промпта). Ошибки сети тихие: секции просто нет.

**Дополнение (0.8.0, решение владельца):** fallback-писатель выбирается —
Claude или DeepSeek (`deepseek-chat`, OpenAI-совместимый chat/completions).
Picker в Settings → General, ключ каждого провайдера в Keychain под своим
account (`claude-api-key` / `deepseek-api-key`). Промпт и правило UNKNOWN общие.

## D-009 · 2026-08-10 · Mac App Store — цель, но отложена до команды владельца

Владелец хочет видеть Rubis Music в App Store. Решение: делать, но **не сейчас** —
старт по его явной команде. До первой строчки кода два гейта, каждый даёт
измеримый ответ:

1. **Hog mode под песочницей.** `AudioDeviceController.startHogging` (SPEC §4,
   эксклюзивный захват) — работает ли у сэндбокс-приложения, проверяется прогоном
   `Tools/audio-verify` в сборке с `com.apple.security.app-sandbox` и живым
   тестом на FiiO QX13. Умрёт hog — MAS-версия перестаёт быть bit-perfect,
   и это развилка владельца, а не Claude.
2. **LGPL в бандле.** `lame` (LGPL v2) и `libsndfile` (LGPL 2.1) приезжают
   бинарными артефактами SFBAudioEngine (`docs/third-party.md`). LGPL требует
   возможности подменить библиотеку, подпись App Store её не даёт — конфликт.
   Проверить, отделяются ли обе от сборки SFBAudioEngine (lame — mp3-энкодер,
   не нужен; libsndfile — WAV/AIFF, покрывается CoreAudio).

Что придётся сделать после гейтов: скоуп bookmark'ов держать и на воспроизведении
(сейчас `startAccessingSecurityScopedResource` живёт только в `LibraryScanner`),
выкинуть из MAS-сборки Sparkle (D-005) и медиа-клавиши через `AXIsProcessTrusted`
(`MPRemoteCommandCenter` остаётся), завести Mac App Distribution-сертификаты,
запись в App Store Connect, privacy labels (Anthropic/DeepSeek/Wikipedia).

**Архитектура — две конфигурации одного проекта, не переезд.** Прямой DMG
(Developer ID + Sparkle + hog) остаётся личным плеером владельца; MAS-таргет —
публичная версия с ограничениями песочницы. Иначе провал гейта 1 стоил бы
bit-perfect ради витрины.

## D-010 · 2026-08-12 · Лицензия — MIT

Репозиторий публичный с сессии 06, но файла лицензии в нём не было: по умолчанию
это «все права защищены», то есть смотреть можно, брать нельзя. Владелец просил
закрыть вопрос и оставил выбор за Claude.

Выбран **MIT**. Решающий довод — D-009: Mac App Store остаётся целью, а условия
Apple конфликтуют с GPL/AGPL (на этом в своё время вылетел VLC). Копилефт закрыл
бы дорогу к витрине ради защиты от гипотетического закрытого форка личного
плеера. Манифест от этого не страдает: путь сигнала всё так же читается глазами.

Вложенные фреймворки живут по своим условиям, включая два LGPL, — реестр в
`docs/third-party.md`, MIT на них не распространяется.

## D-011 · 2026-08-12 · `audio-verify` едет внутри бандла приложения

Доказательство bit-perfect до сих пор было только у того, кто собирает из
исходников. Владелец решил класть его в поставку — ни один конкурент такого не
даёт.

Отдельным файлом в DMG утилита не работает: она линкует десять фреймворков
декодеров через `@rpath`, и рядом с образом их пришлось бы дублировать целиком.
Поэтому бинарь кладётся в `Rubis Music.app/Contents/MacOS/audio-verify` с
`@executable_path/../Frameworks` — он берёт те же фреймворки, что и плеер. Цена
поставки: 4,7 МБ.

Подписывается той же идентичностью, что и приложение (иначе библиотечная
валидация под hardened runtime не пустит фреймворки: «different Team IDs»), с
`com.apple.security.device.audio-input` — без этого TCC молча запрещает захват
петли. После вставки бинаря бандл перезапечатывается, иначе подпись Xcode
становится недействительной.

`Tools/make-dmg.sh` делает это сам и падает, если утилита не стартует из бандла:
такая проверка стоит секунду, а поймать сломанный тракт после нотаризации стоит
целого релиза.

## D-012 · 2026-08-12 · Отчёт о тракте подписывается ключом установки

Отпечаток SHA-256 под отчётом ловил правку текста, но подделывался за секунду:
поменял цифру, пересчитал отпечаток. Владелец просил настоящую подпись.

**Ed25519, ключ свой у каждой установки.** Приватная половина создаётся при
первом отчёте и живёт в связке ключей (`kSecAttrAccessibleWhenUnlocked`,
без синхронизации), публичная печатается в самом отчёте строкой `Key` — поэтому
отдельная «публикация ключа», которая раньше блокировала эту задачу, не нужна.

Что подпись доказывает: текст не правили после выпуска, и два отчёта с одним
ключом вышли из одной установки. Чего не доказывает: что плеер не пересобран.
Ключ локальный, а не сертификат Rubis; вшить общий ключ в приложение было бы
театром — его достанет любой, кто откроет бинарь.

Проверяется двумя способами, оба без доверия к нам на слово:
`audio-verify --verify-receipt <файл>` (утилита едет в бандле, D-011) и
`openssl pkeyutl -verify -pubin -inkey key.pem -rawin` — публичный ключ
разворачивается в PEM двенадцатью фиксированными байтами заголовка
(`ReceiptSigning.pem`).

Связка недоступна (заблокирована, отказ) — отчёт выходит со старым отпечатком,
а не без ничего. Мёртвая запись в связке (не читается, не разбирается в ключ)
удаляется и заводится заново: иначе установка навсегда осталась бы без подписи.

Адверсариальное ревью (Codex) вскрыло три дыры, все закрыты тестами:
подписанному отчёту дописывали свой «вердикт» ниже подписи — теперь строки
`Key`/`Signature` обязаны быть последними двумя; перевод строки в названии
трека (а оно приходит из тегов файла, то есть от кого угодно) дорисовывал
отчёту собственные поля подписи — значения полей теперь всегда однострочные;
трек «Key Largo» ломал разбор. Плюс CRLF из чужого редактора больше не рушит
проверку, а ключ помечен `ThisDeviceOnly` — иначе резервная копия связки
перенесла бы «одну установку» на второй Mac.

## D-013 · 2026-08-12 · Рип с CUE — дорожки внутри общего файла

Диск, слитый одним FLAC плюс `.cue`, до сих пор был в библиотеке одним треком
на час. Владелец попросил читать лист.

**Схема разморожена (v3).** Обещание «схему не трогаем после фазы 2» пришлось
нарушить осознанно: `UNIQUE(source_id, relative_path)` запрещал второй трек в
том же файле, обойти его без миграции нечем. Добавлены `cue_start`/`cue_end`
(секунды, `NULL` у обычных треков), таблица перестроена под новый ключ.

**Границы считает декодер, не плеер.** `CueRegion` переводит секунды листа в
кадры по частоте самого файла, `AudioRegionDecoder` получает `startFrame` и
`frameLength` — конец сегмента приходит как обычный конец файла, поэтому очередь
и склейка gapless работают без единой правки на real-time потоке. Никаких
проверок времени в аудио-колбэке: правило SPEC §4 цело, `audio-verify` после
merge дал те же 24/24.

**Лист главнее тегов.** У рипа одним куском теги описывают весь диск, а названия
дорожек живут только в CUE, поэтому `TITLE`/`PERFORMER`/`DATE` листа перебивают
теги файла; на дорожку без `PERFORMER` идёт исполнитель диска.

Что решено по краям:

- Файл на одну дорожку с началом в нуле не режется вовсе — это обычный трек,
  и лишний `cue_start` мешал бы распознаванию переезда (D-004).
- Лист, чей `FILE` не найден на диске, молча пропускается: рядом с `.cue` часто
  лежит ссылка на давно удалённый `.wav`.
- Дорожки узнаются по `cue_start`, а не по номеру: правка листа не плодит
  двойников и не теряет id вместе с плейлистами и историей. Исчезнувшая из листа
  дорожка удаляется, как и строка «весь файл», если он раньше играл целиком.
- Переезд рипа между источниками по подписи `size+mtime` не ловится — сегменты
  одного файла делят её на всех. Такой рип входит заново, старые строки гасит
  уборка двойников в конце скана.
- DSD с CUE играет файлом целиком: региона `DSDDecoder` не умеет, а DSD раздают
  образом SACD, а не диском с листом.

**Дополнение (сессия 12): границы пришлось выправлять руками.** Тест «сегмент
против полного декода по битам» (`CueDecodeTests`) сразу поймал промах:
`AudioRegionDecoder` отдавал кадры не с начала дорожки, а со следующей границы
блока FLAC. Причина в `SFBFLACDecoder.seekToFrame:` — libFLAC во время самого
seek отдаёт write-колбэком блок с целевым сэмплом, а декодер обнуляет свой
буфер уже ПОСЛЕ, то есть выбрасывает ровно этот блок. Замеры на фикстурах
(блок 16384) легли в модель `landing = (⌊target/bs⌋ + 1)·bs` четыре раза из
четырёх; у WAV через CoreAudio seek точный. Промах — до целого блока (93 мс при
типичных 4096 и 44.1 кГц): у каждой дорожки срезалась бы голова, а хвост залезал
бы на соседнюю.

Лечим у себя, апстрим (SFBAudioEngine 0.13.0, последняя) этого не чинил:
`CueRegion.decoder(url:)` целится на блок раньше нужного, добирает разницу
декодом и отдаёт уже открытый декодер (`AudioPlayer` открывает только то, что
ещё не открыто). Размер блока читается из STREAMINFO двенадцатью байтами файла;
блок плавающий или формат не FLAC — компенсации нет, потому что считать нечего.
Модель прибита тестом: изменится поведение апстрима — тест упадёт, а не тихо
разъедется звук.

Известно и не тронуто: та же кривизна seek живёт в обычной перемотке по треку
(игла транспорта) — там она стоит до блока и прячется внутри одного трека, а
чинить её значит подменять seek у `AudioPlayer`, который считает кадры сам.
